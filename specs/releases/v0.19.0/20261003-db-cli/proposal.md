## なぜ変えるか

5 件はどれも、利用者の手元の DB とそれを作る CLI が、利用者の期待や README と違う動きをする問題である。

- 新しい版の houki-egov-mcp で作った DB を古い版で開くと、全テーブルを消す。`--status` を実行するだけ、`search_fulltext` を呼ぶだけでも消える。約 290 MB の取り込みのやり直しになる（#60）
- README は「書き込みは CLI だけが行い、MCP server は読むだけ」と書くが、`search_fulltext` と `--status` は DB が無ければフォルダーと空の DB を作る（#60）
- `--bulk-download-by-date` を実行すると `last_sync_date` が実行した日になり、その後の `--sync` が取り込んでいない日を飛ばす。差分の無い日は `--bulk-download-by-date` が失敗になり、`--sync` は 1 日ごとに 3 回取り直す（#58）
- 本則が段落だけの法令（改暦ノ布告など）は本文を DB に入れないので、本文から見つからない。公布日を作れないときは実在しない `0001-01-01` を入れる（#59）
- `houki-egov-mcp status` や `--sync --status` のような打ち間違いを知らせず、MCP サーバーとして待ち続けるか、最初のフラグだけを実行する。`--status` の `laws:` は版の数で、警告の「90 日」は設定を変えても変わらない（#61）
- `laws.law_revision_id` に `NULL` が入り、版の値を読めない DB は例外で開けない（#71）

DB のスキーマを変えるのは #59（`promulgation_date` の `NOT NULL` を外す）・#60（`sync_state.schema_version` 列を外す）・#71（`law_revision_id` に `NOT NULL`）の 3 件で、計画書どおり版 3 への 1 回にまとめる。利用者は 0.19.0 で `--bulk-download-everything`（約 290 MB）をやり直す。#58 と #61 はスキーマを変えない。

## Issue ごとの変更

### #58 `last_sync_date` の決め方と差分の無い日

**今の動き（v0.18.0）**: `--bulk-download-everything` の `last_sync_date` は取り込みを始めた時刻の UTC の日付。`--bulk-download-by-date` は `last_sync_date` を実行した日（UTC）にし、同期の状態が無ければ行を作る。差分の無い日（HTTP 500）は、`--bulk-download-by-date` では取り直した後に `[ERROR]` で終了コード 1、`--sync` では取り直した後に「差分なし」。

**変えた後の動き**: `--bulk-download-everything` は取得を始めた時刻を基準にし、`last_sync_date` はその日本時間の日付、`last_full_dl_at` はその時刻。`--bulk-download-by-date` は同期の状態を作らず変えない。差分の無い日（404・500）は、どちらのコマンドも 1 回目の応答で「差分なし」にする。`--bulk-download-by-date` は `--sync` と同じく、先に e-Gov に届くことを確かめ、差分なしなら `  差分なし (HTTP <status>)` を出して終了コード 0。

| 種類     | 仕様 ID                                                      |
| -------- | ------------------------------------------------------------ |
| ADDED    | SPEC-EGOV-CLI-BULK-DOWNLOAD-028                              |
| MODIFIED | SPEC-EGOV-CLI-BULK-DOWNLOAD-017・018、SPEC-EGOV-CLI-SYNC-005 |

| 決めること                                                                                                                 | 答え                                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--bulk-download-by-date` の `last_sync_date` を指定した日にするか、動かさないか                                           | 動かさない（同期の状態に触れない）。指定した日にすると、指定した日が今の `last_sync_date` より後なら間の日を飛ばす同じ不具合が残り、前なら `--sync` が巻き戻る |
| `last_sync_date` を日本時間の日付にするか                                                                                  | する。基準は取得を始めた時刻（取り込みを始めた時刻ではない）。全件の zip が取得の時点の内容なので、取得を始めた日から `--sync` で確かめ直せば漏れない          |
| 差分の無い日の 404・500 を 1 回目で「差分なし」とするか。`--bulk-download-by-date` でも「差分なし」で終了コード 0 にするか | どちらもする。`--bulk-download-by-date` にも e-Gov に届くかの確認を足し、障害の 500 と見分ける                                                                 |

## 実装の変更

- `SCHEMA_VERSION = 3`。`laws.law_revision_id TEXT NOT NULL PRIMARY KEY`、`promulgation_date TEXT`（`NOT NULL` を外す）、`sync_state` から `schema_version` を外す
- DB を開く関数を 2 つに分ける: 作る入口（`--bulk-download-everything` 用。フォルダーとファイルを作り、版を記録し、古い版は呼び出し側の合図で作り直す）と、使う入口（ほかの全部。ファイルが無ければ作らずに「無い」を返し、版を確かめて「同じ・古い・新しい・読めない・記録無し」を返す。書き込まない。MCP サーバーと `--status` は読むだけで開く）。版を読む関数は「整数に読めない」と「行が無い」を分けて返す
- `--bulk-download-everything`: 取得の前に DB の状態を確かめる。古い版なら取得の後で作り直す。取得を始めた時刻を取り込みに渡し、`last_sync_date` は日本時間の日付にする
- `--bulk-download-by-date`: DB の状態の確認 → e-Gov に届くかの確認 → 取得。404・500 は取り直さず「差分なし」。取り込みでは同期の状態を書かない（`updateSyncState: false`）
- `downloadZip()`: 404・500 を取り直さずに投げる指定（差分の取得だけで使う）を足す。全件の取得は今までどおり取り直す
- `--sync`: DB の状態の確認を先に行う。DB が無いときは作らない
- `--status`: 使う入口で開き、DB が無ければ 010 の行、版が合わなければ 011。`laws:` に `count(DISTINCT law_id)` と `count(*)` を出す
- `freshness.ts`: 警告の日数を `BULK_CONFIG.incrementalLimitDays` から作る
- CLI の引数: フラグでない最初の引数と、フラグの後の余分な引数を終了コード 2 にする
- `xml-parser.ts`: 本則に `Article` が無く `Paragraph` があれば `MainProvision` の 1 行を作る。`formatArticleNumForDisplay()` で `MainProvision` → `本則`
- `ingester.ts`: 公布日を作れないときは `null`
- `clearAllData` とそのテスト（`src/db/schema.test.ts` の `clearAllData で laws/articles は消えるが schema_meta は残る` など、仕様 ID の無いもの）を消す
