## なぜ変えるか

- 段落だけの附則の行は、`search_fulltext` で `附則(<n>) intro` と返る。`intro` は e-Gov にも仕様にも無い語で、どの附則の何を指すか分からない。同じ法令でも条のある附則は `附則(7) 1`・`caption: null` で、形がそろわない（#101）
- 数値の環境変数は `Number.parseInt(…) || <既定>` で読むので、`0`・`abc` は黙って既定値になり、負の数はそのまま使う。`HOUKI_EGOV_INCREMENTAL_LIMIT_DAYS=-5` で `--sync` は毎回「上限を超えた」で終わる。0.19.0 から警告の文に上限の日数が出る（SPEC-EGOV-CLI-STATUS-004・SPEC-EGOV-SEARCH-FULLTEXT-023）ので、不正な値がそのまま利用者に見える（#102）

  0.19.0 は DB のスキーマの版を上げて全件を取り込み直す版なので、#101 で DB の値を変えても利用者の取り込み直しは増えない。

## Issue ごとの変更

### #101 段落だけの附則の表示

**今の動き（v0.18.0）**: 段落だけの附則は `article_num: "Suppl<n>_intro"`、`caption` に附則の見出し（`附　則`）の行になり、`search_fulltext` は `附則(<n>) intro` と返す。仕様には書かれていない。

**変えた後の動き**: DB の番号は `Suppl<n>_intro` のまま、`caption` は `NULL`。`search_fulltext` は `附則(<n>)` と返す。

| 種類     | 仕様 ID                         |
| -------- | ------------------------------- |
| ADDED    | SPEC-EGOV-SEARCH-FULLTEXT-041   |
| MODIFIED | SPEC-EGOV-CLI-BULK-DOWNLOAD-012 |

| 決めること（Issue の 1〜3）  | 答え                                                                                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. `search_fulltext` の表示  | `附則(<n>)`（条番号を付けない）。段落だけの本則の `本則`（差分 `20261003-db-cli`）とそろう                                                    |
| 2. DB に入れる番号を変えるか | 変えない（`Suppl<n>_intro` のまま）。表示だけで直り、番号を読むほかの箇所（附則かどうかの判定 `isSupplementaryArticle()` など）に触れずに済む |
| 3. `caption`                 | `NULL`。`caption` は条の見出しの列で、条のある附則・段落だけの本則と同じ扱いにする。附則の見出しは `chapter_path` に残る                      |

### #102 数値の環境変数の検査

**今の動き（v0.18.0）**: 3 つの数値の環境変数は検査せず、`0`・`abc` は既定値、負の数・小数の整数部はそのまま使う。

**変えた後の動き**: CLI（取り込み・同期・状態の表示）は、1 以上の整数でない値で `ERROR: <変数名> は 1 以上の整数で指定してください: <値>` を出して終了コード 2。MCP サーバーは既定値に置き換え、警告を出して起動を続ける。`--help` の使い方に `HOUKI_EGOV_CONCURRENCY` を足す。

| 種類     | 仕様 ID                      |
| -------- | ---------------------------- |
| ADDED    | SPEC-EGOV-CLI-ENTRY-010・011 |
| MODIFIED | SPEC-EGOV-CLI-ENTRY-002      |

| 決めること（Issue の 1〜3）         | 答え                                                                                                                                                                        |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 不正な値の扱い                   | CLI は終了コード 2（案 A）。差分 `20261003-db-cli` の「場面ごとの規則」表 1 の「値の形が違う」と同じ扱い。`0` も不正（試す回数・日数・同時数が 0 では動かない）             |
| 2. MCP サーバーでも同じ検査をするか | 確かめるが終了しない。既定値に置き換えて標準エラー出力に警告を出す。MCP サーバーが起動時に終わると、利用者には MCP クライアントの「接続できない」しか見えないため           |
| 3. ほかの環境変数も同じ規則にするか | 数値の 3 つ全部（`HOUKI_EGOV_CONCURRENCY` を含む）。パスの変数（`HOUKI_EGOV_DB_PATH`・`HOUKI_EGOV_FILES_DIR`・`XDG_CACHE_HOME`）と `DEBUG`・`HOUKI_HUB_EXTENSIONS` は対象外 |

## 実装の変更

- `formatArticleNumForDisplay()`: `Suppl<n>_intro` を `附則(<n>)` にする（`Suppl(\d+)_(.+)` より先に判定する）
- `xml-parser.ts`: 段落だけの附則の行の `caption` を `null` にする
- `src/config.ts`: 3 つの数値の環境変数を 1 か所で読み、「無い・空文字 / 正しい / 不正」を返す。CLI は不正なら終了コード 2、MCP サーバーは既定値と警告。`egov-client.ts` が読み込み時に `createLimit()` を呼ぶので、MCP サーバーの検査はそれより前に済ませる（または読み込み時に既定値に置き換える）
- `--help` の使い方に `HOUKI_EGOV_CONCURRENCY` を足す

## 人が判断すること

1. **（#101）DB の番号を `Suppl<n>_intro` のままにすること。** `Suppl<n>` などに変える案もある（0.19.0 は再取り込みがあるので変えられる）。表示で直るので、番号を読むほかの箇所に触れない側にした。
2. **（#101）`caption` を `null` にすること。** 附則の見出しは `chapter_path` にあるので、条の見出しの列に重ねない。
3. **（#102）`0` を不正にすること。** v0.18.x では `0` は既定値として動いていたので、`0` を「既定値の意味」で書いている設定があれば CLI が終了コード 2 になる。
4. **（#102）CLI が使わない変数も確かめること。** `--status` でも `HOUKI_EGOV_BULK_RETRY` を確かめる。コマンドごとに確かめる変数を分ける案もあるが、規則が単純な側にした。
5. **（#102）MCP サーバーは終了しないこと。** CLI と扱いが分かれる。MCP サーバーの警告は MCP クライアントのログにしか出ない。
6. **承認日。** この proposal.md に承認日と PR 番号を書く。`20261003-db-cli/proposal.md` に足した 2 行の承認もこの PR で行う。
