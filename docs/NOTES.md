## 施行日の当日に配り直される版（0.19.1）

houki-egov-mcp 0.19.0 で作った DB のうち、どれが 0.19.1 の `--bulk-download-everything` を要るのかを説明します。README では「0.19.0 で 2026-10-04 以降に `--sync` した DB は 1 回実行」と広めに案内しています。広めに実行しても、条の本文は入れ直さないので害はありません。

### e-Gov の配り方

e-Gov は、改正が公布された日の差分に、施行日ごとの版を未施行（CSV の未施行の欄が `○`）として入れます。施行日の当日の差分には、同じ版（同じ版の ID、バイト単位で同じ XML）を、未施行の欄を空にしてもう一度入れます（houki-egov-mcp #107。2026-09-01〜10-02 の差分で、`○` から空に変わった版 48 件がすべて施行日の当日の差分だった）。

0.19.0 は XML が前回と同じ版を飛ばしていたので、施行日を過ぎても版が未施行（`UnEnforced`）のまま残り、同じ法令の古い版が現行（`CurrentEnforced`）のまま残りました。`search_fulltext` は現行の版だけを返すので、改正前の条文を返します。

### `--sync` だけで直る DB

`--sync` は、最後に同期した日（`last_sync_date`）を含めて今日までの差分を取り込みます。0.19.0 の最後の `--sync` の `last_sync_date` が、未施行のまま残った版の施行日の当日以前なら、0.19.1 の `--sync` がその施行日の差分を取り込み直すので、状態が直ります。

### `--bulk-download-everything` が要る DB

0.19.0 のまま、施行日の翌日以降まで `--sync` を進めた DB は、その施行日の差分をもう取り込まないので、0.19.1 の `--sync` では直りません。この DB では、0.19.1 の `--sync` と `--status` が次の行を出します。

```
[WARN] 施行日が last_sync_date (<last_sync_date>) より前なのに未施行 (UnEnforced) のままの版が <件数> 件あります。<コマンド> を 1 回実行すると直ります（全件の zip 約 290 MB を取得します。条の本文は入れ直しません）
```

`<コマンド>` は、0.20.0 から `npx -y @shuji-bonji/houki-egov-mcp@latest --bulk-download-everything` の形です。`HOUKI_EGOV_DB_PATH` か `XDG_CACHE_HOME` で DB の場所を決めて実行したときは、同じ変数を前に付けた形になります（0.19.1 では `houki-egov-mcp --bulk-download-everything`）。

`--bulk-download-everything` は、全件の zip の CSV で未施行の欄が空の版を現行にし、全件の zip に入っていない未施行の版（施行されて次の版に置き換わった版）のうち、同じ法令の現行の版の施行日以前のものを前の版（`PreviousEnforced`）にします。条の本文と全文検索の索引は入れ直しません。

`[WARN]` は、施行日が `last_sync_date` より前（同じ日を含まない）の未施行の版を数えます。施行日の当日の差分は当日の 15 時ごろに作られるので、施行日の当日の午前に同期した直後の版は数えません（次の `--sync` で直ります）。
